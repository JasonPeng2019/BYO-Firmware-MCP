## Findings

1. **HIGH — Fresh built-in-only targets cannot complete onboarding.**  
   **Proof:** `server.py:3207-3235` accepts fresh generic support only from a verified CMSIS-Pack; otherwise it clears support and forces research. `server.py:4875-4882` then explicitly rejects a researched built-in target unless accompanied by a pack. Thus a pyOCD built-in target with no appropriate CMSIS-Pack is a permanent setup dead end, despite validation supporting built-ins (`server.py:2451-2454`).  
   **Fix:** Add a server-verified built-in-target authority path: derive/verify target facts and memory map from the connected backend, persist that authority, and allow the research continuation to accept a validated built-in target without requiring a pack.

2. **HIGH — UART onboarding treats every discovered serial device as board-mapped.**  
   **Proof:** `_setup_inventory()` constructs `SerialCandidate` with only its first six fields (`server.py:3280-3289`), leaving `external_adapter=False` and `provably_mapped=True` for every port. The explicit external-adapter confirmation branch in preflight (`setup_flow/preflight.py:357-376`) is therefore unreachable in production inventory. `_confirm_setup_cache()` can then persist the selected port association without physical confirmation (`server.py:3898-3906`).  
   **Impact:** A lone unrelated USB-UART adapter can be silently accepted and later used as the board console.  
   **Fix:** Conservatively classify ports lacking a stable probe/board association as `external_adapter=True, provably_mapped=False`; require the existing friendly confirmation before caching or declaring UART readiness.

3. **HIGH — Generic attach fallback is hardcoded and cannot support boards needing non-default debug transport/clock.**  
   **Proof:** Fresh generic setup tries only `attach/default`, `attach/1 MHz`, and `under-reset/1 MHz` (`server.py:3525-3533`). There is no debug-protocol configuration anywhere in the source, and `PyOCDSWDInterface.open()` exposes only connect mode and frequency (`adapters/swd_pyocd.py:344-374`). `continue_setup` accepts only probe/serial/build choices or target/pack research, not attachment facts (`server.py:4739-4819`).  
   **Impact:** Ordinary targets requiring slower SWD/JTAG or a non-default transport cannot be onboarded or persisted.  
   **Fix:** Add server-controlled, bounded attach negotiation for supported transports and clock rates; verify a successful choice live and persist it in the profile for reuse.
